## Adding a reference document

This can be done entirely on GitHub:

1. Open the [documents folder](https://github.com/auraofintelligence/UNGA81-Luke-Hayes/tree/main/documents). Choose **Add file → Upload files**, upload a public PDF or original document, then commit to `main`.
2. Open [data/references.json](data/references.json), choose the pencil button and find the matching reference number. Add the file path to `links`, update `status` and explain the file in `note`.
3. Commit the edit. The [Actions page](https://github.com/auraofintelligence/UNGA81-Luke-Hayes/actions) shows the automatic checks and deployment. Once green, refresh the public library.

Example link, only after the named file exists:

```json
"links": [
  {"label": "Read the public submission (PDF)", "url": "documents/public-submission.pdf"}
],
"status": "Document available",
"note": "Original public submission, added by the author."
```

Keep the entry’s other fields, including its number and original description. Use simple filenames with hyphens for new documents. Preserve supplied originals unchanged and check hashes before adding another version. Different formats should be explicitly labelled, rather than uploaded as unexplained duplicates. A missing local file fails validation instead of publishing a broken download. This site has no browser upload service; the owner manages files through GitHub.

## Adding or updating a reference link

Edit `data/references.json`. Entries contain `id`, `title`, `category`, `description`, `links`, `status` and `note`. Confirm URLs before adding them, preferably using official institutional sources. Third-party publications can stay as links rather than copied files.

Add new entries using the next unused number, starting at **30**. Preserve original numbers 1 to 29. Use one of the existing categories: `Institutional sources`, `Author documents` or `Connected projects`. Search automatically includes additions.

```json
{
  "id": 30,
  "title": "A clear source title",
  "category": "Author documents",
  "description": "What this source contributes to the discussion.",
  "links": [],
  "status": "Awaiting document",
  "note": "Add the public document when it is ready."
}
```

An entry can have several links. Local paths begin with `documents/`; external URLs begin with `https://`. References have stable addresses such as [`library.html#ref-17`](https://auraofintelligence.github.io/UNGA81-Luke-Hayes/library.html#ref-17).

Entries 13, 22, 23 and 28 have partial links with explanatory notes. The separate 2016 WEF scenario, Try Everything Once, time/intelligence/income resources and Braided Economy resource remain to be added. Unavailable project Pages addresses are omitted; working repositories remain linked.

## Design, accessibility and privacy

Warm ivory, coral, sunshine yellow, sea-glass green and lilac support large editorial type, original illustrations, tactile cards and restrained hover effects. There is a responsive layout, labelled controls, meaningful image alternatives, visible keyboard focus, a skip link, reduced-motion support, print styles and a custom 404 page. Device fonts avoid external font requests.

Reading text and reference links work without JavaScript. JavaScript enhances the compass, reference search and filters, reading progress, section highlighting and menu behaviour. Responsive images have explicit dimensions; lower-page card images load lazily.

There are no analytics, advertising, accounts, third-party embeds or tracking cookies. Search stays in the browser. GitHub hosting and external sites have their own privacy terms.

## Build and preview locally

Python 3.10 or later is enough. No package installation, API key, Node.js build, database or paid service is required. From the repository folder:

```powershell
python scripts/build.py
python scripts/validate.py
python -m http.server 8000
```

Open [localhost:8000](http://localhost:8000). Press `Ctrl+C` in the terminal to stop the preview.

Edit source data or the builder rather than generated HTML. Deployment rebuilds pages on each push, including edits in GitHub’s editor. Refresh generated HTML locally when changing code so repository previews stay useful.

## Publication and verification

GitHub Pages uses **GitHub Actions**. Pull requests run checks; pushes to `main` check and deploy. A failed check prevents publication and the previous successful site remains live. The workflow uses standard GitHub Pages actions, read-only repository permission and scoped deployment permissions. There is no custom domain.

Checks cover local links and anchors, unchanged original PDF bytes, all original reference IDs, body fidelity and eight unique heroes. Browser QA covers 1440px, 390px and 320px layouts, image loading, overflow, keyboard menu dismissal, compass controls, reference filters and empty states, deep links, return-to-top and reading without JavaScript. External links can change; check dates record identification, not permanent availability.
